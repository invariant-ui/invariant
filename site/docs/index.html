Start

Introduction

Invariant compiles your existing design system into one machine-readable contract that AI agents can read and validate against.

It reads React, Vue and Angular components, Storybook stories and design token files. It extracts what is actually there, keeps the evidence for every fact, reports where your sources disagree, and writes a framework-neutral JSON contract. Agents then use it over MCP to learn which components, props and tokens exist, and to check the code they write.

Everything runs locally. There is no account and no network access. Your code is analyzed statically and never executed.

InstallBuild the CLI from source. Quick startFrom zero to a compiled contract. MCP serverGive agents the contract. Validate codeCheck usage against the contract.
StatusReact, Vue, Angular, Storybook and token files are supported. Figma and zeroheight are not supported yet, and the config rejects them with a message.
Start

Install

Invariant is not published to npm yet. Build it from source. You need Node 24 or newer and pnpm.

bash
git clone https://github.com/mcarlucci/invariant.git
cd invariant
nvm use                 # reads .nvmrc (Node 24)
pnpm install
pnpm build

Run it from the checkout:

bash
pnpm invariant --help     # same as: node apps/cli/dist/main.js

Or link it so invariant works from any directory. The agent setup expects this.

bash
cd apps/cli && pnpm link --global

Check your setup with pnpm verify. It runs lint, typecheck, package boundary checks, build and tests.

Start

Quick start

Run these inside the project that holds your design system.

bash
invariant init                          # detect sources, write invariant.config.json
invariant compile                       # write the contract to ./invariant
invariant compile --watch               # or keep it up to date: recompile when sources change
invariant components list               # browse what was found
invariant components inspect Button --evidence
invariant tokens list
invariant conflicts list                # where sources disagree
invariant agent init claude-code        # connect an AI tool

init detects a source for each framework package, for Storybook and for token files. If your layout is unusual, add sources by hand with invariant source add <type> [path] or edit the config.

Add --cwd /path/to/project to any command to run it against another directory.

With --watch, compile keeps running and recompiles after your changes settle, so a connected agent always sees a current contract. Press Ctrl+C to stop. Every cycle recompiles all sources.

Compile exit codecompile exits 1 if any diagnostic is an error. The files are still written so you can inspect the problem.
Concepts

How it works

Each stage has one job and a clear boundary.

text
sources  ->  adapters  ->  IR  ->  reconcile  ->  enrich  ->  verify  ->  contract
(code)       (extract)    (shared)  (merge,       (infer,      (check)      + evidence
                                     conflicts)   with
                                                  evidence)
  1. Discover. Find packages, entry points, Storybook configuration, token files and docs.
  2. Extract. Each adapter reads one kind of source and emits facts with evidence into an intermediate representation (IR). Adapters never merge or resolve, and do not know about each other.
  3. Reconcile. A pure compiler merges the IR from every source into one contract. Disagreements become conflicts, never silent overwrites.
  4. Enrich. A deterministic semantic engine adds clearly labeled inferred facts, such as a token's category.
  5. Verify. The output is checked for structure, references, hashes and evidence before it is written.

Adapters must not independently generate the contract, and the contract is not coupled to any frontend framework or to MCP.

Concepts

The contract

The contract is one JSON file, invariant.contract.json. Think of it as a catalog of everything in your design system, where every entry points to the proof for it. The Zod schema in packages/contract defines it, and JSON Schemas generated from it are committed under packages/contract/schema/.

Anatomy of one entry

Every entity keeps plain values next to a facts map. The map says, for each field, how it is known and where the proof is. This sketch is illustrative and trimmed.

json
{
  "id": "component:button",
  "name": "Button",
  "props": [
    { "name": "variant", "allowedValues": ["primary", "secondary", "ghost"] }
  ],
  "implementations": [ { "framework": "react", "exportName": "Button" } ],
  "facts": {
    "props.variant.allowedValues": {
      "status": "discovered",
      "evidenceIds": ["ev_3f9a..."]      // resolves in invariant.evidence.json
    }
  }
}

Fact paths are dot-separated (props.size.default, modes.theme:dark.value). On an array, a segment picks the item with that name or id. See Facts and evidence for the four statuses.

Concepts

Facts and evidence

Every field of every entity has a fact that says how it is known. This is how Invariant keeps discovered information separate from guesses.

StatusMeaning
discoveredMachine-parsed from an artifact whose structure is the claim, such as a TypeScript prop type.
documentedWritten by a person in prose or guidance, such as a JSDoc description.
inferredDerived by a named deterministic rule. Always carries a derivation and a confidence. Adapters never emit it.
approvedAccepted by a named person. Layered over the earlier status, which is kept as priorStatus.
text
status:      discovered | documented | inferred | approved
evidenceIds: at least one id into invariant.evidence.json
confidence:  0..1, required when inferred
derivation:  { rule, reasoning, inputs }, required when inferred
approval:    { approvedBy, approvedAt, role?, reference?, fingerprint, priorStatus }

Evidence

Evidence lives in invariant.evidence.json, referenced by id. Each entry records the source, the location (file and line), the extraction method and the original text. Ids are ev_ plus 24 hex characters of a SHA-256 over the immutable parts of the observation.

Approvals expire

An approval stores a fingerprint of the entity id, path and value at the time it was made. If the value changes, verification reports contract.approval-stale. An approval cannot silently outlive the thing it approved.

RuleInferred rules are never automatically promoted to approved policies, and LLMs are never the authority for extractable facts such as TypeScript APIs, props, exports, defaults or token values.
Concepts

Conflicts and review

When two sources disagree, both claims stay in the contract with their evidence. The losing claim is never deleted.

Conflict types

value-mismatch, existence-mismatch, deprecation-mismatch, identity-ambiguity and token-value-mismatch. Ids look like conflict:<type>/<subject>/<path>. Resolution starts as open.

Storybook findings with evidence on both sides become conflicts, for example arg-value-not-allowed or default-mismatch. A story arg that a component's type does not allow is caught this way.

Review queue

invariant.review.json lists every open conflict and every inferred fact that needs a person, each with evidence, a reason and approvalRequired: true. Work through it with the CLI:

bash
invariant review list
invariant review show <id>
invariant review approve <id> --as "Jane Doe" --role "design-system lead"
invariant review reject <id> --as "Jane Doe"
invariant review accept <id> --as "Jane Doe" --note "known difference"

See Decisions for what each command does.

Sources

React

Source type react. Uses the TypeScript compiler API and type checker. Nothing is executed or imported.

What counts as a component

Only components exported from a package's entry points are reported. Aliases, renames, export *, default exports and barrels are followed, so one component exported under several names is one entity.

FormRule
Function or arrowPascal-case name and returns JSX
Annotated functionPascal-case, declared React.FC<P>, FunctionComponent<P> or VFC<P>
ClassExtends Component or PureComponent
WrappersforwardRef, memo (nesting allowed), lazy (props unknown)
CSS-in-JSTagged templates from styled-components or @emotion/styled
CompoundObject.assign(Root, { Child }) and Root.Child = Child

Hooks, lowercase functions, constants and functions without JSX are not components. Higher-order components and unrecognized factory calls are reported with a diagnostic and not analyzed.

Facts extracted

  • Props: type text and kind, required, default, allowed values in declaration order (through aliases), JSDoc description and deprecation.
  • Variants: string-literal union props and cva configs.
  • Slots: children, renderable-typed props and render props.
  • Accessibility: a static role and every aria-* attribute on native elements in the component's own body.
  • Styling: CSS modules, var(--x) references, class names and Tailwind, recorded as written and never resolved to tokens.
  • Composition: which public components this one renders.
  • Usage: static counts of props across JSX sites. These are source counts, never runtime frequency.
CompletenessWhen props cannot be fully listed (a base type from outside the project, lazy, an untyped parameter), the component is marked propsComplete: false. Treat an absent prop as unknown unless propsComplete is true.
Sources

Vue and Angular

Source types vue and angular. Both produce the same neutral facts as React, so a component's contract looks the same whichever framework it came from. A test checks one Button implemented in all three.

Vue

Public components are the .vue files and defineComponent(...) declarations that entry points export. Extracted: defineProps, runtime props, defineModel, defineEmits, defineSlots merged with template <slot> outlets, and Options API props. Imports of .vue files resolve through virtual script modules, so a props type declared in another SFC works.

Angular

Public components and directives are the decorated classes that entry points export. Extracted: @Input, input(), input.required(), model(), @Output with EventEmitter, output(), and <ng-content> slots from the template. @NgModule classes become entities of kind module.

Neutral mapping

ConceptReactVueAngular
Propspropspropsinputs
Eventscallback props (kept as props)emitsoutputs
Slotschildren, render propsslotsng-content

Events differ on purpose: React callbacks stay props with role: event-handler, while Vue emits and Angular outputs are events.

Path aliases from tsconfig (paths, baseUrl, extends, references) are resolved for all adapters. Package-name extends is not followed.

Sources

Storybook

Source type storybook. Stories are read statically from CSF files and MDX. No Storybook process is started and no story code runs.

Supported forms

CSF 3 object stories, CSF 2 function stories, Template.bind({}) stories, and CSF 2 assignment annotations such as Story.args = .... Meta can be an object literal, an identifier, or wrapped in satisfies, as or parentheses. When component is absent, Meta<typeof X> is used.

Static evaluation

args, argTypes and parameters are evaluated by a small static evaluator. It resolves literals, objects, arrays, const identifiers (across files), property access and object spread. It never guesses. Functions, JSX, calls, template literals with substitutions and unresolvable identifiers are listed under an ...Unresolved fact by key path.

Linking stories to components

A story links to its component through the file and localName pair the component adapter publishes. Display names are never used for linking. Because of that, the project root is the configuration's directory, so all sources share one set of project-relative paths.

What reconciliation reports

Conflicts: arg-value-not-allowed, control-option-not-allowed, default-mismatch, arg-undeclared, control-undeclared and deprecated-demonstrated. Coverage findings such as prop-not-demonstrated and component-unlinked stay diagnostics.

Sources

Design tokens

Source type tokens, adapter id design-tokens. It is its own package because tokens are not React-specific.

CSS custom properties

Each declaration yields a name, raw value and line. Scope is classified conservatively:

  • :root, html, :host and body are the default value.
  • [data-theme="x"] (also data-mode, data-color-scheme, data-color-mode), .dark, .light, .theme-x, and @media (prefers-color-scheme: ...) around a root selector are theme modes.
  • Anything else is component-private and gets no value or mode fact.

JSON

W3C Design Tokens files ($value, $type, {path} aliases, $description, $deprecated) and Style Dictionary files (value, type, comment). Evidence carries the line of each token's key.

What it does not decide

Category, semantic name, and the mapping between a CSS variable name and a JSON token name are not decided here. Tokens from different files merge on a normalized name (color.brand equals color-brand), recorded as an inferred fact. A different literal or alias for the same token and theme is a token-value-mismatch conflict.

Use it

Configuration

invariant.config.json is read as data. init writes it for you.

json
{
  "name": "Acme Design System",
  "contractId": "acme-design-system",
  "sources": [
    { "id": "ui-library", "type": "react", "path": "packages/ui" },
    { "id": "storybook", "type": "storybook", "path": "packages/ui" },
    { "id": "tokens", "type": "tokens" }
  ],
  "output": { "directory": "invariant" }
}

Sources

  • type is one of react, vue, angular, storybook, tokens. zeroheight and figma are rejected as not supported yet.
  • path limits an entry to sources found at or below that directory. Without it, the entry covers the whole project. Several entries of one type are combined. A type with no entry is not run.
  • id is a label. compile and analyze print which compiled sources each entry produced, and warn with cli.source-matched-nothing when an entry matched none.
  • All paths must be relative, with no .., no absolute paths and no backslashes. The output directory defaults to invariant.
  • The neutral inventory adapters (packages, Markdown documentation, token files, Storybook configuration) always run.

Other settings

KeyPurpose
validation.rulesSeverity or off per rule code. Unknown codes are rejected with a suggestion.
validation.failOnDefault failing threshold for validate.
validation.ignoreGlobs validate skips.
governance.policiesFilePath to the policies file. Default invariant.policies.json.
governance.approversOptional list of names allowed to record and apply decisions.

Code configuration

invariant.config.ts, .mts, .mjs or .js with a default export also works, but loading one executes it. It is only loaded with --trust-config. source add and source remove never edit it, because that would mean running it. They tell you to edit it by hand or to run invariant init, which writes invariant.config.json. A JSON file wins over code files when both exist.

Use it

MCP server

invariant mcp serves the compiled contract over stdio, read-only. The contract does not know MCP exists: the server only reads the files compile wrote.

bash
invariant compile
invariant mcp [--dir invariant]     # serves until stdin closes

Tools

All ten are read-only and deterministic. Results are JSON in structuredContent and in the text content, always with contractHash. Lists take offset and limit (default 50, at most 200). Results over 400,000 characters are refused with advice to narrow the request.

ToolReturns
get_design_system_overviewName, frameworks, sources and health, counts, open conflicts, inferred-fact count, and what is not covered.
search_design_systemLexical hits over components, tokens and guidelines with score and what matched. Handles plurals, prefixes and one-letter typos. Fixed ranking; no model or embeddings.
get_componentImplementations (with apiComplete), props with type, default, allowed values, status and source line, events, slots, variants, accessibility, conflicts, guidelines.
get_component_usageHow to import, required props, variants and defaults, deprecated props, source examples, observed prop combinations (React only).
get_component_compositionWhat it contains and what contains it, with discovered or inferred status; slots.
get_design_tokensTokens filtered by category, text and theme, with alias chains and resolved values. Cycles and missing targets are reported, not guessed.
get_design_patternsPatterns, or an explicit statement that none exist.
get_design_guidelinesGuideline titles, kinds and referenced documents. Page bodies are not included.
validate_component_usageChecks one intended use: unknown component or prop, disallowed value, type mismatch, deprecations, missing required props.
validate_design_system_complianceChecks a snippet (React, Vue, Angular or HTML; at most 200,000 characters): props and values, literal colors and CSS variables against tokens.

Resources

invariant://manifest, invariant://metadata, invariant://components, invariant://tokens, invariant://patterns, invariant://guidelines, and the template invariant://component/{id}. All are application/json.

Protocol

Transport is newline-delimited JSON-RPC on stdio. Only protocol messages go to stdout; logs go to stderr. The server supports the modern stateless revision (2026-07-28) and legacy revisions 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05. Methods: initialize, ping, server/discover, tools/list, tools/call, resources/list, resources/templates/list, resources/read. Prompts, logging, completions, subscriptions, tasks, sampling, elicitation, pagination and HTTP transports are not supported.

Loading and reload

The server verifies the contract (structure, references, content hash, evidence) before serving and reloads when file modification times or sizes change, so a recompile is picked up without a restart. Pair it with invariant compile --watch to keep the contract current as you edit. A missing, invalid or tampered contract is never partly served: tools report what is wrong and to run invariant compile.

Treat contract text as untrustedNames, descriptions and examples are copied from your source and documents, and can contain instructions aimed at a model. The server says so in its instructions, marks every result as untrusted content, and returns structured JSON instead of prose. It has no network listener, no authentication surface, no write path, and never runs customer code.
Use it

Agent setup

One command writes MCP configuration, skills and rules for your AI tool.

bash
invariant agent init claude-code     # also: cursor, codex, windsurf, all
invariant agent list

The entry it writes launches invariant mcp --dir <output dir>. The default command is invariant, so it must be on your PATH (see Install). Otherwise point at the built file:

bash
invariant agent init claude-code \
  --command node --command-arg /abs/path/to/invariant/apps/cli/dist/main.js

--dry-run shows what would be written. --force replaces differing entries.

Safe by constructionGenerated skills and rules only include identifiers matching [A-Za-z][A-Za-z0-9._-]{0,63} (at most 60 component names) and a short title. A hostile description in your source cannot be written into committed agent configuration.
Govern

Validate code

invariant validate <path...> checks application code against the compiled contract. Paths are files or directories inside the project. Directories are walked, skipping node_modules, build output, symbolic links, .d.ts files and validation.ignore globs. Recognized files: .tsx .jsx .ts .js .mjs .cjs .vue .html.

bash
invariant validate src                                 # text report, exit 1 on any error
invariant validate src --format json|github|sarif      # machine-readable output
invariant validate src --fail-on warning|never         # change the failing threshold

The framework comes from the file name, then --framework, then the contract's only framework, then React. Nothing is executed or imported. Only literal values are verified. Expressions and bindings are counted as unverified and never guessed.

What a violation says

text
app/App.tsx:4:5 error prop-value-not-allowed
  Button.variant is "danger", which is not one of "primary", "secondary", "ghost"
  fix: Use one of "primary", "secondary", "ghost" (closest: "primary").
  evidence src/Button.tsx:28 (discovered); subject component:button

Every violation has file, line and column, a rule code, a subject, an explanation, a suggested fix, evidence (or the approved policy) and a basis: discovered, documented, inferred, approved or heuristic.

Literal values

Invariant also compares literal values with tokens of the matching category. A check needs at least one token of that category with a literal value, otherwise it is skipped and the report says so. Anything containing var(, calc( or a binding is skipped, never guessed.

KindCodesReads
Colorcolor-not-in-tokens, color-matches-tokenHex, rgb()/rgba(), hsl()/hsla() and CSS named colors. Hex and functional colors compare by value, so rgb(0 87 255) equals #0057ff. Names are read only as the value of a color property and match a token by name.
Spacingspacing-not-in-tokens, spacing-matches-tokenLengths in margin*, padding* and gap, in CSS or style objects. rem and em use a 16px root. Zero, auto and percentages are skipped.

Govern

Policies

Organizational rules are written by people in invariant.policies.json, kept in version control.

json
{ "version": 1, "policies": [ {
  "id": "icon-buttons-need-labels",
  "name": "Icon-only buttons need an accessible name",
  "statement": "A button without text content must have aria-label or aria-labelledby.",
  "severity": "error",
  "enforcement": "block",
  "approval": {
    "approvedBy": "Jane Doe",
    "approvedAt": "2026-01-05T00:00:00.000Z",
    "role": "design-system lead",
    "reference": "RFC-7"
  },
  "rule": {
    "kind": "require-attribute",
    "components": ["Button"],
    "anyOf": ["aria-label", "aria-labelledby"],
    "unlessChildren": true,
    "category": "accessibility"
  }
} ] }

Rule kinds: require-attribute, forbid-prop, forbid-prop-value, forbid-component, forbid-token, allowed-children and required-parent.

  • A policy without approval is rejected. Nothing infers or auto-approves a policy.
  • Policies take their severity from the file, lowered by enforcement: warn caps at warning, report-only is info.
  • compile adds each policy to the contract, so validate reads only the contract.
  • A policy that names a component or token the contract lacks is kept and reported as governance.policy-unknown-component. That part cannot fire.
  • Composition checks are conservative: required-parent only fires when the element sits inside other design-system components and none is an allowed parent.

List approved policies with invariant policy list. There is no policy add yet; write the file by hand.

Govern

Decisions

Decisions are written to invariant.decisions.json and applied on every compile.

CommandEffect at compile
review approve <id>The fact becomes approved, layered over its prior status, with a fingerprint and your --role, --reference and --note.
review reject <id>Removes an inferred containment link, guideline link or token category. Other inferred facts cannot be rejected; the reason says how to fix it at the source.
review resolve|accept|dismiss <id> [--source s]Records the conflict's resolution: resolved (fixed at the source), accepted (a known difference) or dismissed (not a real conflict). The conflict disappears on recompile once the source is fixed.

Every decision needs --as <name> (or the INVARIANT_USER environment variable) and records when it was made.

Stale decisions

A decision records the value or claims it was made about. If they change, the decision is stale: it is not applied, compile reports governance.decision-stale, and the item returns to the queue. A decision whose target is gone is reported as governance.decision-target-missing.

Authorization is not authenticationThe recorded name is asserted, not proven. governance.approvers restricts which names the CLI will record and compile will apply. Real enforcement is your repository's review process over invariant.policies.json and invariant.decisions.json, for example CODEOWNERS.
Govern

Verify in CI

Exit codes plus output formats are the integration. --format github prints workflow annotations, --format sarif prints SARIF 2.1.0 for code scanning, and --format json is for scripts.

bash
invariant compile
invariant verify --fresh                       # fails if stale or tampered with, and says what changed
invariant validate src --format github         # annotate pull requests

Commit the invariant/ folder, invariant.config.json, invariant.policies.json and invariant.decisions.json. Compiling unchanged sources gives identical bytes, so diffs are meaningful.

compile writes these to the output directory (default invariant/).

FileContents

--keep-ir adds ir/ and invariant.project.json. Only the manifest holds the build time, so all other files are reproducible.

The report is self-contained: no scripts, no external requests, a restrictive Content-Security-Policy, and every value from your source is HTML-escaped. Every table lists every row: the first 200 are visible and the rest are folded into a <details> block.

The contract stays valid and useful alone. If the evidence file is missing, facts keep their status and you get a diagnostic, not an invalid contract.

Safety model

  • No code execution. Source is parsed, never run. The one exception is an explicitly trusted code configuration (--trust-config).
  • Writes stay inside the output directory. export writes only inside its --to directory. Artifact paths are checked against escaping.
  • No secrets. The configuration has no credential fields, so there is nowhere to put one.
  • No absolute paths. Absolute paths and hostnames never enter the contract or evidence. Paths are POSIX-relative to a recorded source root.
  • Untrusted text. Anything copied from your source is treated as data by the MCP server and agent kit.

Known limitations

What Invariant does not do today. Where it cannot tell, it says so in the output instead of guessing.

Sources and extraction

  • Figma and zeroheight are not supported. The config rejects them with a message.
  • Third-party types are not loaded. Props inherited from library types (HTML attributes, other design systems, VariantProps) are listed as inherited, not enumerated, and the component is marked propsComplete: false. Because of that, many Storybook arg and control checks end as unverifiable-names.
  • React components made by factory functions, and higher-order components, are reported but not analyzed. Accessibility facts cover only static attributes on native elements in the component’s own body.
  • Vue: components registered only through a plugin, components exported under a different local name than their import, <script src> and <template src> blocks, and non-HTML template languages such as pug are not read (each is reported). Generic components are marked incomplete.
  • Angular: template semantics such as structural directives, pipes and template references are not modeled. Members from hostDirectives are not enumerated, and types from inject() stay unknown.
  • Usage statistics (usage.* and observed prop combinations) exist for React only.
  • Storybook is read statically. Global preview args, parameters and decorators, URL args and dynamically generated stories are not read, MDX is scanned and not compiled, and stories for components that are not public are reported as unlinked.
  • Extraction was validated on a small set of real libraries, including one Vue and one Angular library. Treat other libraries as unvalidated.

Contract and inference

  • Patterns are not produced. A pattern needs a description of intent, which static facts do not supply, so patterns list says none exist.
  • requires-parent relationships, accessibility requirements and layout patterns are not produced by any compiler. They work only through approved policies.
  • Name-based identity is a heuristic, marked as such. It cannot link Buttons to Button or Button / Primary to Button.
  • Compound inference is naming-based and proposes some wrong parents, for example Button and ButtonGroup. These get confidence 0.4 to 0.7 and sit in the review queue.
  • A guideline’s kind is read from its title and file name only. Developer documents such as changelogs and contributing guides also become reference guidelines.
  • The token model is a literal or an alias, per theme. Composite values are kept as JSON. Token values are compared as the adapter reports them, so a whitespace-only difference is a mismatch.
  • When sources conflict, the entity keeps one value. Read the conflict list to see the others.
  • Evidence excerpts are capped at 2,000 characters.
  • The review queue lists every inferred fact, so it is long on large libraries (437 items for Radix). It is ordered by priority, with no filtering or batch approval.

Validation and governance

  • validate sees one file at a time: no cross-file data flow, no resolution of wrapper components, and no knowledge of which package an unimported tag comes from. React unknown-component detection depends on imports. Vue and Angular detect components by name or selector only.
  • Name-based findings (native-element-has-equivalent and ambiguity) are heuristics.
  • Colors are compared by value after converting to hex. hsl() conversion rounds, so a hex token and an hsl literal can differ by one step. Named colors match only a token with the same name. oklch(), color(), lab() and Tailwind class names are not read.
  • rem and em literals are compared against a 16px root font size.
  • Policies have seven rule kinds and cannot express arbitrary logic. They are written by hand: there is no policy add.
  • Approver names are asserted, not authenticated. Enforce who may approve through your repository review process.
  • Rejecting an inferred identity cannot split it between implementations, and a conflict decision does not change the contract’s kept value.

CLI and MCP

  • No incremental compile. Every run, including each compile --watch cycle, recompiles all sources.
  • source add and source remove cannot edit a code configuration, by design, because editing it would mean running it.
  • init detects by package manifests and discovery. Unusual layouts need source add or a hand edit.
  • The MCP server speaks a protocol subset: no HTTP transport, authentication, subscriptions or pagination. Search is lexical: it matches words, plural and -ing stems, prefixes and one-letter typos (labeled approximate), but not synonyms or meaning.
  • The MCP validators check literal values in one snippet. They do not resolve imports or follow props through wrappers.
  • The server cannot record decisions. People record them with invariant review.
  • Windsurf’s MCP configuration could not be verified, so agent init windsurf prints the entry instead of writing it.

Contributing

The repo is a pnpm workspace with explicit package boundaries. apps/cli is the command, and packages/* hold the adapters, compiler, contract, validation, governance, MCP server and agent kit.

bash
pnpm build             # tsc -b
pnpm test              # vitest
pnpm lint              # biome
pnpm typecheck
pnpm check:boundaries  # enforce package boundaries
pnpm verify            # lint + typecheck + boundaries + build + test
pnpm update:golden     # regenerate golden fixtures

Engineering rules

  • TypeScript strict mode, small composable modules, deterministic compilation, structured diagnostics.
  • Unit tests for extraction logic, integration tests for adapters, golden fixtures for regressions.
  • Contract changes are versioned: update the schema and runtime validation, add migration logic when needed, and update fixtures and tests.
  • Significant architecture decisions are recorded as ADRs in docs/decisions/.

The detailed specifications live in docs/specifications/.
